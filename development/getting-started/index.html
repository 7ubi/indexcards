    Getting Started¶

    This page describes how to run Indexcards locally for development.

    Requirements¶

    Tool Version Used for
    Java (JDK) 11 Backend
    Maven 3.6+ Backend build (or use ./mvnw)
    Node.js 22+ Frontend
    MySQL 5.7 Database (e.g. via Docker)
    Python 3.9+ Documentation (optional)

    Login for local development¶

    The app has no own login anymore; it needs Authentik:

    1. Create a Google OAuth client (see Deployment → Login) with the redirect URI http://localhost:9000/source/oauth/callback/google/.

    2. Create .env in the repository root (not committed):

      AUTHENTIK_SECRET_KEY=<openssl rand -base64 60 | tr -d '\n'>
AUTHENTIK_PG_PASSWORD=<random>
AUTHENTIK_BOOTSTRAP_PASSWORD=<admin password>
AUTHENTIK_BOOTSTRAP_EMAIL=<your email>
AUTHENTIK_URL=http://localhost:9000
INDEXCARDS_URL=http://localhost:4200
GOOGLE_CLIENT_ID=<client id>
GOOGLE_CLIENT_SECRET=<client secret>

    3. docker network create nginx_backend (once), then docker compose up -d mysqldb authentik-db authentik-server authentik-worker.

    4. Start the backend (./mvnw spring-boot:run; its defaults point to http://localhost:9000) and the frontend (npm start), open http://localhost:4200, click Sign in or create account and use Sign up (or Google).

    Database¶

    The backend expects a MySQL database indexcardsdb on port 3306 (host from MYSQL_HOST, default localhost) with user root and password 12345678. The quickest way is a Docker container:

    docker run -d --name indexcards-db -p 3306:3306 \
  -e MYSQL_DATABASE=indexcardsdb -e MYSQL_ROOT_PASSWORD=12345678 \
  mysql:5.7

    The schema is created automatically by Flyway on the first start of the backend.

    Backend¶

    cd indexcards
./mvnw spring-boot:run

    The backend starts on http://localhost:8080. It validates the access tokens issued by Authentik, so Authentik has to be running (see Login for local development). Uploaded images are stored in ./data/images (see configuration).

    Tests¶

    The tests use JUnit 5 and an in-memory H2 database, so no MySQL is needed:

    ./mvnw clean package                                     # build and run all tests
./mvnw test -Dtest=CreateIndexCardServiceTest            # single test class
./mvnw test -Dtest=CreateIndexCardServiceTest#methodName # single test method

    Frontend¶

    cd indexcards-ui
npm install
npm start

    The app is available on http://localhost:4200. The dev server proxies all requests to /api/** to the backend on http://localhost:8080 (see src/proxy.conf.json).

    Command Description
    npm start Dev server with live reload
    npm run build Production build into dist/
    npm test Unit tests (Vitest)
    npm run lint ESLint
    npm run format:check Check formatting with Prettier
    npm run format Fix formatting with Prettier

    Lint and format are checked in the pipeline, so run them before pushing.

    Documentation¶

    cd indexcards-docu
pip install -r requirements.txt
mkdocs serve

    The documentation is then available on http://localhost:8000.

    Full stack with Docker¶

    The docker-compose.yml in the repository root starts MySQL, backend and frontend together. It is meant for the deployment and requires an external Docker network; for development running the parts separately as described above is simpler.

    Versioning¶

    Backend and frontend share one version number. To change it, run

    scripts/bump-version.sh 2.3.0

    This updates the version in indexcards/pom.xml, the jar name in indexcards/Dockerfile and indexcards-ui/package.json.
